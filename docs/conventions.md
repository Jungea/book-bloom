# 개발 규칙

> 확인: 2026-11-26
> 상태: 초안. 기존 문서에서 확정된 개발 원칙과 `제안`·`미정` 항목을 구분해 모았다. 새 기술 결정을 만들지 않는다.

## 1. 계층 분리 (확정)

- React: 독서관리 UI, HUD, 팝업, 메뉴.
- Phaser: 배경·시설·책 렌더링, 입력, 카메라.
- 순수 TypeScript 게임 코어: 도서 재고·배치, 보상 규칙. Phaser와 React에 핵심 규칙을 두지 않는다.
- 저장소 인터페이스: 로컬 저장·복원을 분리해 이후 서버 동기화를 붙일 수 있게 한다.
- 저장 데이터를 불러오지 못했거나, 복원하지 못한 데이터를 따로 보관하지 못하면 게임을 시작하지 않고 오류 화면만 보인다(`src/data/loadGame.ts`, `src/App.tsx`). 빈 상태로 시작해 다음 저장이 기존 데이터를 덮어쓰는 일을 막기 위해서다.

근거: `06-architecture.md` 06-3.

## 2. 폴더 구조 (제안, 승인 전)

`src/app`, `src/game`, `src/core`, `src/reading`, `src/data`, `src/shared`, `src/debug`, `public/assets`, `tests`, `docs`, `android`.

실제 구조는 분석 후 사용자 승인을 받아 정한다 (`00-ai-guide.md` 5절). 승인 전에는 이 목록을 따라 폴더를 만들지 않는다. 승인받아 만든 폴더: `src/core`, `src/debug`, `src/data`, `src/reading`. 독서관리 임시 화면(`ReadingScreen.tsx`)은 새 폴더 없이 `src/reading`에 두었다.

## 3. 에셋과 렌더링

- 파일명은 영문 소문자 snake_case (`05-asset-guide.md`).
- 확대는 nearest-neighbor. 책장에는 책을 그려 넣지 않고 개별 책등을 코드로 렌더링한다.
- 좌표와 앵커는 상수로 관리하고 manifest 기준으로 맞춘다. 슬롯 중심 X는 80/240/400/560, 바닥 기준선 Y는 240 (V4 제작 기준).
- 논리 해상도(640×360 vs 1280×720)는 **미확정**이다. Android 실기기 검증 후 결정하므로 해상도에 묶인 수치는 한곳에 모은다.
- 게임 UI 텍스트는 가능한 한 코드에서 렌더링한다.

## 4. 개발자 테스트 모드 (확정)

- 실제 게임 로직을 호출한다.
- 테스트 데이터는 실제 데이터와 분리한다.
- 일반 출시 빌드에서는 비활성화한다. 패널은 개발 서버와 `--mode debug` 빌드(`npm run build:debug`, `npm run android:sync:debug`)에서만 켜지고, 일반 빌드는 코드가 번들에서 빠진다.
- 저장소 이름도 분리한다. 디버그 빌드는 `bookbloom-debug`, 일반 빌드는 `bookbloom`을 쓴다 (`src/App.tsx`).
- v0.1: 임시 도서 등록, 1권·10권 획득, 책장 채우기, 저장·복원·초기화 (`08-roadmap.md`).
- 독서 동작 버튼: 테스트 도서 등록, 시작·완독·재독 시작·완독 취소·삭제를 패널에서 실제 독서 코어(`src/reading`)로 실행한다. 버튼은 현재 독서 상태에서 코어가 허용하는 동작만 보여 주고, 거절된 동작은 사유를 표시한다 (`src/debug/readingActions.ts`).

## 5. 테스트와 검증

- 규칙을 바꾸면 관련 테스트와 문서를 함께 고친다.
- 타입 검사나 테스트가 실패한 상태에서 다음 기능으로 넘어가지 않는다.
- 검증 결과는 `통과` / `실패` / `미실시`로 기록한다. 실제로 실행하지 않은 PC·Android 검증은 완료로 표시하지 않는다.
- 단위 테스트(Vitest)와 웹 E2E(Playwright)는 후보 스택이다. 의존성 추가는 승인 후 한다.

## 6. 의존성과 범위 (확정)

- 필요한 단계에만 의존성을 추가하고, 추가 전에 사용자와 결정한다.
- 현재 버전 범위 밖 기능과 `10-ideas.md`의 미승인 아이디어는 앞당겨 구현하지 않는다.
- 무관한 리팩터링과 전체 재작성은 하지 않는다.
- 기존 저장소(Bookhive, my-library, PageRoom)는 읽기 전용 참조이며, 재사용 결정은 `06-4-reuse-guide.md`에 기록한다.

## 7. Git

- 기능 단위 커밋. 정상 상태에는 태그, 큰 구조 변경 전에는 복구 지점을 만든다 (`08-roadmap.md`).
- 원격 푸시와 파괴적 작업은 사용자 승인 후 한다. 비밀 정보는 커밋하지 않는다.
- 커밋 메시지는 한국어로 쓴다.
- (제안) Codex와 Claude Code의 비교 개발 시 도구별 브랜치를 쓴다. 작업이 반려되면 기존 브랜치를 고치지 않고 번호를 붙인 새 브랜치(`claude/compare-dev-2` 등)에서 다시 시작한다. 합의된 규칙이 아니므로 확정 시 갱신한다.

## 8. 완료 보고 항목 (확정)

목표, 수정 파일, 참조한 저장소·파일, 실행한 검증과 결과, 미해결 오류, 미구현 사항, 다음 작업, Git 상태 (`AGENTS.md`, `00-ai-guide.md`). 개발 일지는 `09-development-log.md` 양식을 쓴다.

## 9. 현재 코드와의 차이 (사실 기록)

`src/game/LibraryScene.ts`는 에셋 경로와 좌표 상수가 씬 파일 안에 있고, 데스크 모니터 위치가 `FLOOR_Y - 73`으로 고정되어 있다. 게임 코어와 IndexedDB 저장 계층은 구현됐으며, 좌표 상수의 분리는 이후 관련 작업에서 검토한다(장면 기준 좌표와 손님 경로는 `sceneLayout.ts`·`visitorLayout.ts`로 일부 분리했다).

현재 코드의 역할 분담(2026-11-27, v0.3 개발 중):

- `src/core/` 순수 TypeScript 코어(Phaser·React 무관): `library`(책장·보관함·대출 기록 타입), `circulation`(예약·대출·만기·반납 대기·정리·회수), `visitors`·`visitorWorld`(손님 상태 머신과 메모리 월드, 도서관과는 훅으로만 연결), `returnSorter`(트레이 정리).
- `src/reading/` 독서 기록과 도서관을 함께 다루는 게임 상태(`gameStore`), 저장 형식(`gameSnapshot` v3, v1·v2 복원), 코어를 저장소에 잇는 훅(`gameCirculation`).
- `src/data/` 저장소 계층: IndexedDB 저장, 복원·복구(`loadGame`), 순차 저장(`persistGame`).
- `src/game/` Phaser 장면과 순수 보조 함수(좌표, 임시 상수, 표시 규칙, 진행률 링).
- `src/debug/` 개발자 테스트 패널(디버그 빌드에서만).
- 대출·정리의 규칙을 바꿀 때는 `core`에서 바꾸고 테스트를 함께 고친다. 장면은 코어 상태를 그리고 클릭을 코어로 전달할 뿐 규칙을 두지 않는다.
