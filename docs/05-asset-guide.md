# 05. 그래픽 및 에셋

> 확인: 2026-11-26
> 상태: 노션 원문 이관. 문서 안의 확정·제안·미정 표기를 그대로 따른다.

## 05-1. 공통 그래픽 방향 (확정)

- 정면 벽면을 바라보는 아늑한 2D 픽셀아트. 도서관은 가로형이며 벽면 시설과 바닥 이동 공간을 분리한다.
- 개별 도서와 시설, 캐릭터를 독립 에셋으로 구성한다. UI는 아이콘 버튼을 우선한다.
- 초기에는 도서 두께를 고정 1슬롯으로 처리하고, 추후 얇음·보통·두꺼움 3등급을 적용한다.

## 05-2. 공통 화면 및 배치 규격

- 확정: 방마다 벽면 4슬롯. 초기 배치는 데스크 / 책장 / 빈 슬롯 / 반납트레이.
- 아래 수치는 제작 기준안이며 최종 해상도 및 2슬롯 시설 적용은 미확정이다.

### 화면 규격

| 영역 | 논리 크기(px) | 2배 제작 기준(px) |
| --- | --- | --- |
| 전체 화면 | 640 × 360 | 1280 × 720 |
| 상단 상태바 | 640 × 32 | 1280 × 64 |
| 벽면 및 시설 | 640 × 208 | 1280 × 416 |
| 바닥 및 이동 공간 | 640 × 120 | 1280 × 240 |
| 개별 슬롯 | 160 × 208 | 320 × 416 |
| 슬롯 내 최대 가구 영역 | 144 × 192 | 288 × 384 |

- 슬롯은 가로 4개, 중심 X 좌표는 80, 240, 400, 560px. 벽면 시설의 공통 바닥 기준선은 Y=240px.
- 슬롯 좌우 최소 여백 8px, 가구 배치 기준점은 하단 중앙. 가구마다 높이와 너비는 다르게 유지한다.
- 대형 가구는 연속된 2슬롯을 점유할 수 있다. 간판·벽면 장식은 부착형, 캐릭터는 자유 이동형으로 관리한다.
- 논리 좌표는 640×360 기준, 실제 신규 원본은 2배 픽셀 크기로 제작하는 안을 적용한다. 단순 확대가 아니라 원본 디테일을 확보하고 정수 배율 렌더링을 사용한다.

### 배치 검수 (제안)

- manifest.json에 논리 크기, 원본 크기, 슬롯 점유 수, 하단 중앙 앵커, 충돌 영역, 클릭 영역, 부착 좌표를 기록한다.
- 가구를 슬롯별로 교체해도 바닥 기준선과 좌우 여백이 유지되어야 한다. 부착물과 업무 소품을 합친 전체 크기도 슬롯 경계를 검수한다.
- 2슬롯 가구는 인접 슬롯을 함께 예약하여 중복 배치를 방지한다.
- 방 확장 시 기본 도서관, 도서 홍보관, 독서 열람실, 특별 도서관 등 동일한 4슬롯 구조를 재사용한다.
- 실제 레퍼런스와 캐릭터 비율, 책등 가독성, 화면 크기별 표시를 테스트한 후 최종 해상도 및 개별 크기를 확정한다. 위 수치는 제작 기준안이며 기존 에셋은 변경하지 않는다.

## 05-4. 공통 제작 규격 (제안)

### 파일 및 렌더링 규격 (제안)

- PNG RGBA: 개별 오브젝트 외부는 투명 배경, 배경 타일은 필요에 따라 불투명.
- 벽면과 바닥은 별도 파일로 분리하고 반복 가능한 텍스처는 경계가 자연스럽게 연결되도록 제작한다.
- 책장에는 책을 미리 그리지 않는다. 선반별 책 배치 좌표를 제공하고 개별 책등을 두께 등급과 색상으로 동적 렌더링한다.
- 캐릭터는 방향별 프레임 크기와 발 위치가 동일한 스프라이트 시트로 제공한다. 대기·걷기 상태와 프레임 순서를 명시한다.
- 대출반납데스크와 반납트레이는 독립 오브젝트로 제작하고, 반납 책의 유무를 별도 레이어 또는 상태별 파일로 표현한다.
- 공통 시점, 픽셀 밀도, 광원, 비율을 유지한다. 확대는 nearest-neighbor를 사용한다.
- 영문 소문자 snake_case 파일명을 사용한다. 게임 UI 텍스트는 가능한 한 코드에서 렌더링한다.
- manifest.json에 파일 경로, 원본 픽셀 크기, 앵커(배치 기준점), 충돌 영역, 선반 슬롯, 애니메이션 프레임 정보 등 해당 에셋에 필요한 메타데이터를 기록한다.
- `README.md`에 렌더링 순서, 사용 예시, 크기 규칙, 출처 및 라이선스를 기록한다.

### 공통 서비스 적용 요구사항

- 각 버전 내부에서 일관된 정면 시점, 픽셀 밀도, 광원, 색상 계열 및 투명 PNG 규격을 사용한다.
- 본체, 가림 레이어, 그림자, 교체 가능한 콘텐츠는 필요한 경우 각각 독립 파일로 제공한다. 글자·숫자·책 표지·진행률은 이미지에 고정하지 않고 데이터와 연동한다.
- 홍보 전시대는 동일한 본체에 간판과 도서 표지를 교체하여 이달의 도서, 신착 도서, 사서 추천, 테마 전시를 구현할 수 있게 한다. 도서 표지는 사용 권한이 확인된 이미지 또는 대체 표지를 사용한다.
- manifest.json에 에셋 ID, 파일 경로, 픽셀 크기, 배치 앵커, 충돌 영역, 클릭 영역, 레이어 순서, 슬롯 좌표 및 크기, 상태별 이미지 경로를 해당되는 항목에 한해 기록한다.
- 열람석은 착석 위치·방향·이동 접근점, 카트는 이동 기준점, 화면형 시설은 화면 영역, 게시판과 간판은 텍스트 표시 영역을 정의한다.
- 도서가 없거나 데이터가 로딩되지 않을 때 빈 상태를 지원한다. 실제 대출·반납, NPC 이용, 업적 해금 규칙은 게임 기획에서 별도로 확정한다.

## 05-5. 상태 표현 및 애니메이션 (확정)

### 책장 내 대출 상태 표현 (확정)

- 개별 도서의 책장 내 위치를 고정한다.
- 대출 중인 도서는 원래 위치에 반투명 쉐이프로 표시한다.
- 반납 정리 완료 시 원래 위치에 정상 도서 에셋을 복원한다.
- 구체적인 투명도, 색상 및 애니메이션은 추후 결정한다.

### 손님 도서 선택 시각 표현 (확정)

- 손님이 책장에서 도서를 선택하는 즉시 원래 책장 슬롯을 반투명 쉐이프로 변경한다. 대출 완료 시점까지 기다리지 않는다.
- 선택한 도서 에셋을 손님 머리 위에 표시하며 대출 데스크 이동 및 대기 중에도 유지한다.
- 구체적인 표시 크기, 애니메이션 및 대출 완료 이후 표시 여부는 추후 결정한다.

### 하트 획득 연출 (확정)

- 대출 완료 시 손님 머리 위에 하트 에셋을 표시하고 상단 재화 UI로 이동하는 애니메이션을 적용한다.
- 별도 수집 클릭 없이 자동 획득한다.
- 구체적인 색상, 크기, 이동 시간 및 이펙트는 추후 결정한다.

### 시설 업그레이드 외형 원칙 (확정)

- 책장 업그레이드 시 기존 디자인 테마를 유지하면서 선반을 추가한다.
- 성능 레벨에 따른 강제 디자인 테마 변경은 적용하지 않는다.
- 스킨 변경은 초기 에셋 제작 범위에서 제외하고 개발 최후반부에 선택적으로 검토한다.

## 05-6. 제작 및 검수 기준

- 게임 개발 순서는 08. MVP 및 개발 로드맵을 따른다. 에셋 제작 후보의 우선순위는 게임 기능 적용 확정을 의미하지 않는다.
- 기존 에셋을 삭제·수정·덮어쓰기하지 않는다.

### 추가 제작 우선순위 (제안)

- 우선: 표지형 홍보 전시대, 교체형 간판, 낮은 진열장, 장르 분류 표지판 — 기존 독서 데이터와 연동 가능한 전시 기능.
- 다음: 도서 운반 카트, 무인 대출반납기, 도서 검색대, 1인 열람석, 공용 열람 테이블 — 운영 및 NPC 기능.
- 이후: 공지사항 게시판, 독서 목표 현황판, 트로피 진열장 — 콘텐츠 및 성장 기능.

- [ ] 데스크와 트레이의 배치 및 상태 변경이 가능하다.
- [ ] manifest.json 경로와 실제 파일이 일치한다.
- [ ] 사용 권한과 라이선스가 확인된다.
