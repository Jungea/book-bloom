# 게임 규칙 (v0.1 중심)

> 확인: 2026-11-26
> 상태: 초안. 기존 문서의 확정 규칙을 v0.1 중심으로 모았다. 재독·과거 기록·시설 확장 등 후속 구현 규칙도 참고용으로 포함하며, 이 문서가 로드맵의 구현 범위를 넓히지는 않는다. 충돌하면 근거 문서와 명시적 확정 문구를 따른다.

## 1. 범위

v0.1 "나만의 도서관"을 중심으로 다룬다. 손님, 대출·반납 실행, 하트·평판, 방 확장, 애니메이션은 v0.1에서 제외한다 (`08-roadmap.md`).

v0.1 완료 기준은 `08-roadmap.md`를 따른다. 최초 독서 시작·최초 완독 보상, 책장 진열·보관함 및 저장·복원을 먼저 구현한다. 아래 재독 완료, 과거 기록 입력, 추가 시설 설치에 관한 규칙은 해당 기능의 구현 단계에서 적용한다.

> 개발 적용 기록 (2026-11-27): 사용자 승인에 따라 재독 완료 보상의 순수 TypeScript 코어와 단위 테스트를 `claude/reading-record`에서 먼저 반영했다. 독서관리 화면과 릴리즈 완료 범위는 `08-roadmap.md`를 따르며, 이 코어가 있다는 사실만으로 재독 기능의 출시를 완료로 표시하지 않는다.

## 2. 도서 획득 (확정)

| 상황 | 획득 | 근거 |
| --- | --- | --- |
| 읽고 싶은 책 등록 | 없음 | 03 |
| 최초 독서 시작 | +1권 | 02, 03 |
| 최초 완독 | +1권 (동일 도서) | 02, 03 |
| 재독 시작 | 없음 | 03 |
| 재독 완료 (코어 선반영, 화면 후속 구현) | +1권 (동일 도서) | 02, 03 |
| 일시 중단·하차 | 기존 도서 유지, 추가 없음 | 03 |
| 독서 재개 | 추가 없음 | 03 |
| 독후감·별점 작성 | 도서 수 변화 없음 | 03, 07-1 |

- 독후감은 도서 획득 조건이 아니다.
- 진행률 100%에 도달해도 자동 완독하지 않는다. 사용자가 직접 확정한다.

### 과거 기록 입력 (확정 규칙, 후속 구현)

읽는 중 1권, 과거 최초 완독 2권, 과거 재독 완료는 회차당 1권. 읽고 싶은 책은 보상 없음 (03).

## 3. 중복 방지와 회수 (확정)

- 보상 지급 이력(`reading_rewards`)으로 중복 지급을 막는다 (03, 07-1).
- 완독 취소 시 완독 보상을 회수하고, 독서 이력 삭제 시 해당 회차 보상을 회수한다. 도서 삭제 시 연결된 게임 도서를 제거한다.
- 날짜 수정은 보상에 영향을 주지 않는다. 제목·저자 수정은 게임 도서 정보를 갱신한다.
- 회수 대상 도서가 책장·보관함·반납 트레이에 있으면 즉시 제거한다.
- 대출 중인 회수 대상 도서는 반납 시점에 제거한다. 하트·평판은 유지한다. (대출은 v0.3 이후)

## 4. 도서관 초기 상태 (확정)

- 방 1개, 시설 슬롯 4개. 왼쪽부터 데스크 / 책장 / 빈 슬롯 / 반납 트레이 (02).
- 기본 시설은 무료. 하트·평판은 0.
- 데스크와 트레이는 v0.1에서 표시만 한다 (00).

## 5. 책장 배치 (확정)

- 모든 도서는 1슬롯을 점유한다 (02).
- 획득 순서대로 비어 있는 책장 슬롯에 순차 자동 배치한다.
- 기존 도서 위치는 자동 재정렬하지 않는다.
- 빈 슬롯이 없으면 초과 도서 보관함에 저장한다. 보관함 도서는 대출할 수 없다.
- 책장 추가로 빈 슬롯이 생기면 보관함 도서를 획득 순서대로 앞쪽 빈 슬롯부터 자동 배치한다 (추가 시설 구현 시).
- 책장 설치 순번은 이동·업그레이드 시 유지하고, 철거 후 재설치·신규 설치 시 마지막 순번을 부여한다. 자동 배치는 설치 순번 기준이다.

## 6. 도서 상태 (확정, 일부만 v0.1)

`AVAILABLE`(진열) → `RESERVED`(선택·예약) → `ON_LOAN`(대출) → `RETURNED`(반납 대기) → `AVAILABLE`. 진열 공간이 없으면 `STORED`(보관, 대출 불가) (07-3).

v0.1에서 사용하는 상태는 `AVAILABLE`과 `STORED`뿐이다. 나머지는 v0.3 이후에 도입한다.

## 7. 미정 (임의로 정하지 않는다)

- 책장 용량, 시설 가격, 장르 전문성 수치, 보상 수치. (코드의 `TEMP_SHELF_CAPACITY`는 선반에 물리적으로 들어가는 개수를 쓴 테스트용 임시 상수이며 확정 규칙이 아니다.)
- 저장 복원 시 책장 용량이 저장 당시와 다를 때의 처리. 현재 코드는 넘치는 도서를 보관함 앞쪽으로 옮기고, 늘어난 빈 슬롯에는 보관함 도서를 획득 순서대로 채운다. 임시 용량이 바뀔 때를 위한 임시 처리이며 확정된 기획 규칙이 아니다(`02`의 "책장 추가" 규칙을 참고한 것).
- 보관함 도서 수는 도서관 화면 상태바에 `보관함 N권` 텍스트로 임시 표시한다. 위치·모양은 `04-ui-ux.md`에 명세가 없어 정해지지 않은 임시 표시이며 확정된 UI가 아니다(`src/game/LibraryScene.ts`).
- 독서 기록 변경으로 책장 도서가 회수되어 빈 슬롯이 생길 때, 코드는 보관함의 가장 오래된 도서를 그 슬롯으로 올린다. `02`의 "빈 슬롯이 확보되면 보관함 도서를 자동 배치"를 회수 상황까지 넓혀 해석한 임시 처리이며 확정된 기획 규칙이 아니다.
- 1회차 독서 이력을 삭제한 뒤 2회차 이후가 남아 있을 때 최초 독서 시작 보상을 다시 줄지 여부. 현재 코드는 다시 주지 않는다.
- 도서 크기 3등급의 기준과 도입 버전.
- 수동 책장 할당의 방식과 도입 버전.
- 책장 철거 시 대출 중 도서의 상세 처리는 02의 "책장 철거 시 도서 재배치"를 따르며, v0.1에서는 해당 없음.

## 8. 테스트해야 할 규칙 (제안)

순수 TypeScript 코어의 단위 테스트 대상 후보이다.

- 독서 시작·최초 완독·재독 완료의 획득 수량.
- 같은 이벤트를 두 번 처리해도 한 번만 지급.
- 일시 중단·하차·재개·재독 시작·독후감에서 수량 불변.
- 슬롯이 가득 찼을 때 보관함으로 이동, 슬롯이 늘면 보관함에서 자동 배치.
- 기존 도서 위치 불변.
- 완독 취소·이력 삭제·도서 삭제 시 회수.
- 과거 기록 입력 시 수량 (읽는 중 1, 최초 완독 2, 재독 회차당 1).
