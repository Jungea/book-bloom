# 09. 개발 기록

> 확인: 2026-11-26
> 상태: 노션 원문 이관. 문서 안의 확정·제안·미정 표기를 그대로 따른다.

## 현재 상태

기획 단계. 실제 개발 작업은 아직 기록되지 않았다.

## 기록 양식

- 작업 날짜
- 작업 내용
- 기술적 의사결정 및 이유
- 발생 문제와 해결 방법
- 다음 작업

## 기술 검증 기록 기준

실제 검증 후 날짜, Git 커밋, PC 브라우저·Android 기기 및 OS, APK 빌드, 화면 배율, 입력, NPC 이동, 렌더링 성능, 테스트·타입 검사, 문제와 해결 결과를 기록한다. 현재 실기기 검증 결과는 미기록이며 완료로 간주하지 않는다.

## 개발 기록 관리 체계 (확정)

실제 개발 시작 이후 작업 단위로 기록을 누적한다. 개발 계획과 실제 구현·검증 결과를 구분한다.

| 기록 항목 | 내용 |
| --- | --- |
| 개발 일지 | 날짜별 작업 내용 |
| 버전별 변경사항 | 추가·수정·삭제 기능 |
| 오류 및 해결 기록 | 원인과 해결 방법 |
| 테스트 기록 | 자동 테스트·PC 웹·Android 실기기 결과 |
| 기술 변경 이력 | 기술 스택 및 라이브러리 변경 |
| 코드 재사용 기록 | 기존 프로젝트 참조 및 재사용 코드 |
| 미해결 문제 | 오류 및 기술 부채 |
| 서버 사용량 | Supabase 용량·전송량·비용 |

- Android 실기기 테스트 결과:
- 발생한 문제 및 해결 방법:
- 미완료 사항:
- 다음 작업:
- Git 커밋 및 태그:
실제 수행하지 않은 테스트는 미실시로 기록한다. 현재는 기록 체계만 확정하며 실제 개발 결과는 개발 시작 후 작성한다.
