# 04. UI/UX 설계

> 확인: 2026-11-26
> 상태: 노션 원문 이관. 문서 안의 확정·제안·미정 표기를 그대로 따른다.

## 확정된 화면 방향

벽면을 정면으로 바라보고 바닥에서 캐릭터가 2D 이동. 방향 버튼으로 방 전환.

## 레이아웃 제안

- 상단: 도서관 상태
- 중앙: 벽면 책장과 이동 영역
- 하단 또는 측면: 책 등록, 독후감, 방 이동
- 책 클릭: 상세 정보 팝업

## 후속 작업

와이어프레임, 모바일 대응, 이동 버튼 위치 결정.

## 시설 슬롯 배치 방식 (확정)

- 방마다 벽면에 시설 배치 슬롯 4개를 제공한다.
- 사용자는 각 슬롯에 원하는 시설을 배치하여 방별 시설 조합을 구성할 수 있다.
- 시설 업그레이드 시 기존 슬롯을 유지한다.
- 자유 좌표 배치 방식은 적용하지 않는다.
- 바닥은 손님 이동 공간으로 활용한다.
- 시설 이동 및 교체 방식, 초기 슬롯 구성, 시설별 설치 제한은 추후 결정한다.

## 방 단위 공간 확장 (확정)

- 평판 조건을 충족한 후 하트를 소비하여 신규 방을 개방한다.
- 최초 방뿐 아니라 모든 개방된 방의 상하좌우 인접 미개방 공간으로 연속 확장할 수 있다.
- 이미 개방된 좌표에는 방을 중복 생성하지 않는다.
- 신규 방은 빈 시설 슬롯 4개를 제공한다.
- 전체 방 개수가 증가할수록 확장 비용이 점진적으로 증가한다.
- 방향 버튼으로 인접한 개방된 방으로 이동한다.
- 구체적인 평판 조건, 하트 비용 및 최대 방 개수는 추후 결정한다.

## 도서관·독서 관리 화면 전환 (확정)

- 도서관(타이쿤)과 독서 관리 영역은 독립 화면으로 구성하고 양방향 화면 전환 방식으로 이동한다.
- 도서관은 가로형(Landscape), 독서 관리는 세로형(Portrait)으로 구성한다.
- Android에서는 각 영역에 맞춰 화면 방향을 전환하는 구조로 설계한다.
- 두 영역의 UI는 독립적으로 구성하되 도서 데이터를 공유한다.
- PC 웹의 세로형 화면 배치, 최초 실행 화면, 독서 관리 중 게임 운영 방식 및 화면 방향 전환의 기술 구현은 추후 확정한다.

## PC 웹 화면 배치 및 아이콘 중심 UI (확정)

- PC 웹에서도 도서관은 가로형으로 구성하고 독서 관리는 화면 중앙에 세로형 콘텐츠로 배치한다.
- 도서관과 독서 관리의 양방향 화면 전환 구조를 유지한다.
- 전체 UI에서 텍스트 버튼보다 아이콘 버튼을 가능한 한 우선 사용한다.
- 구체적인 아이콘 디자인, 보조 설명 방식, 버튼 배치 및 크기는 추후 UI 상세 설계에서 결정한다.

## 플랫폼별 사용 경험

- PC는 독서관리 중심의 데스크톱 UI 및 마우스, Android는 타이쿤 중심의 터치 UI. 기능·게임 규칙·에셋은 공통이며 양쪽 전체 화면 플레이 지원.
- 기존 확정 방향: 게임 가로형, 독서관리 세로형. Android 방향 전환 구현은 실기기 검증 대상이며 화면 이동으로 게임 상태를 초기화하지 않는다.
- 기본 진입 화면 제안: PC 독서관리 대시보드, Android 타이쿤. 미확정.

## 독서 관리 화면 색 테마 (사용자 확정, 2026-11-27)

독서 관리 화면의 임시 최소 화면에 "화이트 + 슬레이트" 테마를 쓴다. 색 테마만 확정이며 레이아웃·아이콘 UI·기본 진입 화면 등 최종 UI는 계속 미정이다.

- 배경·폼·도서 목록·입력 면 `#ffffff`, 주요 글자 `#354047`, 버튼·강조 `#3a5668`, 보조 글자 `#687178`, 구분선(테두리) `#dedfdd`.
- 도서 목록은 카드 테두리·배경·모서리·그림자 대신 항목 사이의 여백과 구분선으로 나눈다.
- 색은 `src/style.css`의 `.page--reading` 안 CSS 변수(`--reading-bg`·`--reading-text`·`--reading-accent`·`--reading-muted`·`--reading-border`와 면·눌림·삭제·안내 보조 토큰) 한 블록에서만 정한다. 테마를 바꾸려면 이 값만 고친다. SCSS는 `sass` 의존성이 필요하고 SCSS 변수만으로는 실행 중 테마 전환이 되지 않아(SCSS 안에서도 CSS 변수는 쓸 수 있다) 이번에는 의존성 없이 CSS 변수만 썼다.
- 도서관 게임 화면(어두운 바탕, 캔버스)과 게임 에셋의 색은 이 테마와 무관하게 유지한다.

## 글꼴 (사용자 결정, 2026-11-28)

- 도서관(타이쿤) 화면의 글자(Phaser `보관함 N권`, `반납 N권`)도 독서 관리 화면과 같은 글꼴 목록(`system-ui, sans-serif`)을 쓴다. 목록은 `src/uiFont.ts`의 `UI_FONT_FAMILY` 한 곳에서 정하고 `src/style.css`의 body와 같아야 한다(테스트가 확인한다). 전용 웹폰트는 쓰지 않으며 기기 시스템 글꼴을 따른다.

## 독서 관리 화면 아이콘 (사용자 확정, 2026-11-27)

독서 관리 화면과 화면 전환 버튼의 아이콘은 `lucide-react`를 쓴다(새 의존성은 이 선택으로 승인). 아이콘 세트·적용 규칙만 확정이며 최종 레이아웃은 계속 미정이다.

- 사용자용 React 화면에만 적용한다. 개발자 패널과 Phaser 도서관 화면(게임 에셋)에는 쓰지 않는다.
- 색은 `currentColor`라 화이트 + 슬레이트 테마 토큰(버튼 글자색)을 따른다. 크기 18px, 선 두께 2로 통일한다(`src/reading/icons.ts`).
- 뜻이 분명한 동작(화면 전환, 수정, 삭제, 수정 취소)은 아이콘만 쓴다. 한국어 `aria-label`(도서 제목 포함, 예: `작은 숲의 기록 삭제`)과 PC 툴팁(`title`)을 반드시 넣는다.
- 화면 전환 버튼(사용자 결정, 2026-11-28): 도서관의 `독서 관리` 버튼과 독서 관리 화면의 `도서관으로 돌아가기` 버튼은 **같은 아이콘(`BookOpen`)의 원형 아이콘 버튼(48px)** 이고 글자는 보이지 않는다. 접근성 이름과 툴팁은 각각 `독서 관리`, `도서관으로 돌아가기`다.
- 헷갈릴 수 있는 동작은 아이콘과 글자를 함께 쓴다: 독서 상태 동작(`읽고 싶음`·`시작`·`재개`·`완독`·`일시 중단`·`하차`·`재독 시작`·`완독 취소`)과 `도서 등록`·`저장`.
- 터치 영역은 모든 버튼 44px 이상이다. 아이콘만 있는 버튼은 정사각형 44px이고, 화면 전환 버튼은 원형 48px이다.
- 동작 이름과 아이콘의 짝은 `src/reading/actionIcons.ts`에서 정하고 새 동작을 추가하면 테스트가 아이콘 누락을 잡는다.
