# 00. AI 개발 시작 가이드

> 확인: 2026-11-26
> 상태: 노션 원문 이관. 문서 안의 확정·제안·미정 표기를 그대로 따른다.

## 1. 목적 및 현재 상태

BookBloom(북블룸)은 실제 독서 활동으로 도서관을 성장시키는 경영 중심의 힐링·수집 타이쿤이다. PC 웹과 Android를 지원하며 iOS는 초기 제외한다. 현재 기획 단계이며 실제 코드 분석·구현·실기기 검증은 별도 수행해야 한다. 이 페이지는 AI 개발 진입점이며 상세 기획을 대체하지 않는다.

## 2. 필수 문서 및 읽는 순서

첫 작업에서는 01, 06, 06-4, 08을 먼저 읽고 나머지 02~05, 07, 09, 10도 확인한다. 이후 작업별 관련 문서와 최신 변경 기록을 다시 읽는다.

- 01. 프로젝트 개요 — 서비스 목표·이름·플랫폼
- 02. 게임 기획 — 게임 규칙
- 03. 독서 관리 기획 — 독서 기록·보상
- 04. UI/UX 설계 — 화면 전환·슬롯
- 05. 그래픽 및 에셋 — 에셋 규격·버전
- 06. 기술 설계 — 아키텍처·개발 규칙
- 06-4. 기존 프로젝트 참조 및 코드 재사용 가이드 — 저장소별 참조 범위

## 3. 문서 해석 원칙

- 최신 확정 사항을 오래된 초안·제안보다 우선한다. 상충하는 확정 사항은 사용자에게 확인하고 임의 해결하지 않는다.
- 상위 페이지의 과거 독후감 중심 루프는 현재 보상 규칙보다 우선하지 않는다. 최초 독서 시작 +1권, 최초 완독 +1권, 재독 완료 +1권이며 독후감 자체는 도서 획득 조건이 아니다. 재독·리뷰 상세 구현은 로드맵을 따른다.
- 02의 과거 오프라인 무제한 보상 문구보다 최신 8시간 보상 한도 정책을 우선한다. 한도는 하트·평판에만 적용되며 운영은 계속된다.
- 06의 초기 Next.js 후보보다 최신 React/Vite/Phaser/Capacitor 우선 채택안을 따른다. 실기기 검증 후 확정한다.
- 05의 640×360 논리/1280×720 원본은 제작 기준안이며 최종 논리 해상도와 2슬롯 시설은 미확정이다.
- 08의 기술 검증 단계는 릴리즈 기능 범위를 확대하지 않는다. 10의 아이디어는 승인 전 구현하지 않는다.

## 4. 저장소와 리소스

신규 BookBloom 저장소에서만 개발한다. 기존 저장소는 참조 전용이며 병합하거나 전체 복제하여 계승하지 않는다.

- [Bookhive](https://github.com/Jungea/Bookhive): Phaser 씬, React 연동, 캔버스·스프라이트·에셋 로딩.
- [my-library](https://github.com/Jungea/my-library): 순수 게임 규칙, 상태 머신, 테스트, 독서 보상 연결.
- [PageRoom](https://github.com/Jungea/PageRoom): 독서관리 UI·기록·데이터 구조.
- 로컬 원본 에셋 `assets/source/`: 버전별 에셋. 실제 파일·manifest·README와 V4 수정 상태를 확인하고 사용 버전을 보고한다.
로컬 폴더는 BookBloom과 기존 3개 저장소를 같은 상위 폴더에 두는 것을 권장한다. 실제 경로와 접근 권한을 먼저 확인한다. 재사용은 직접·수정·설계 참조·제외로 분류하고 파일 경로, 이유, 테스트를 기록한다.

## 5. 개발 구조 및 문서 준비

우선 기술: TypeScript, React, Vite, Phaser, Capacitor. 초기 IndexedDB, 서버 연동은 후속 단계에서 Supabase. React UI / Phaser 렌더링 / 순수 TypeScript 게임 코어 / 저장소 계층 분리. 신규 의존성은 필요 시 승인 후 추가한다.
권장 폴더(제안): src/app, src/game, src/core, src/reading, src/data, src/shared, src/debug, public/assets, tests, docs, android. 실제 구조는 분석 후 승인받는다.
Git 루트에 `AGENTS.md`, `CLAUDE.md`, `README.md`를 준비하고 두 AI 지침은 공통 docs를 참조한다. docs/`project-overview.md`, `game-design.md`, `game-rules.md`, `reading.md`, `ui-ux.md`, `asset-guide.md`, `architecture.md`, `database.md`, `roadmap.md`, `reuse-guide.md`, `conventions.md`, `development-log.md`를 권장한다. 노션 원문 링크 및 확인 시점을 기록하고 확정/제안/미정 상태를 유지한다. 문서 접근 실패 시 내용을 추측하지 말고 필요한 내보내기 파일을 요청한다.

## 6. Phase 0 — 첫 작업 (분석 및 준비 계획)

1. 노션 문서 및 접근 가능한 기존 저장소, 로컬 개발 환경, 에셋을 확인한다.
2. 기존 저장소 기술 스택·폴더 구조·재사용 후보 파일·알려진 문제를 분석한다.
3. 신규 아키텍처, 최소 의존성, PC/Android 실행 검증 계획과 v0.1 작업 단위를 제안한다.
4. `AGENTS.md`, `CLAUDE.md` 및 공통 개발 문서 초안을 준비한다.
5. 분석 결과, 충돌·미정 사항, 접근 실패, 필요한 사용자 결정을 보고하고 승인을 기다린다.
이 단계에서는 실제 게임 기능 구현, 기존 코드 이식, 원본 수정, 원격 푸시를 하지 않는다. 실제 파일 생성 및 환경 구축은 사용자 승인 범위에 따라 진행한다.

## 7. v0.1 구현 범위 및 순서

08의 확정 순서: 프로젝트 초기 세팅·PC 실행 → 배경 및 4슬롯 → Android APK·실기기 → 화면 크기·터치 → 독서관리 코드 선별 재사용 → 독서와 게임 도서 획득 연동 → 책장 진열 및 로컬 저장 → 통합 테스트.
초기 방: 데스크 / 책장 / 빈 슬롯 / 반납 트레이. 도서관 가로형, 독서관리 세로형, 양방향 전환. 개별 도서 1슬롯, 획득 순서 배치, 초과분 보관, 독서 시작·첫 완독 각각 +1권 및 중복 방지, 등록·수정·삭제, 저장·복원. 개발 초기부터 실제 게임 로직을 호출하는 임시 도서 획득 테스트 버튼을 제공하고 테스트 데이터 분리 및 출시 빌드 비활성화를 적용한다.
제외: NPC, 대출·반납 실행, 하트·평판, 방 확장, 애니메이션, Supabase·계정, 후속 콘텐츠. 데스크와 트레이는 초기 화면 표시만 한다. 08의 완료 체크리스트를 기준으로 검증한다.

## 8. 공통 AI 작업 지침

- 작업 전 관련 문서와 Git 상태 확인, 요청 범위 및 수정 대상 명시.
- 기존 저장소 수정, 승인 없는 기술·규칙·범위 변경, 신규 의존성, 무관한 리팩터링 및 전체 재작성 금지.
- 기존 사용자 변경사항 보존, 비밀키 커밋 금지, 원격 푸시·파괴적 작업은 별도 승인.
- 게임 규칙 변경 시 테스트·문서 함께 갱신. 자동 테스트 및 타입 검사, PC 웹, Android APK·실기기 검증. 미실시 검증은 미실시로 기록.
- 실패 시 신규 기능 중단, 데이터 저장 오류 우선 해결, 마지막 정상 상태와 비교. 기능별 커밋 및 정상 버전 태그로 복구 지점 관리.
- 완료 보고: 목표, 수정 파일, 참조 저장소·파일, 실제 실행한 테스트와 결과, 미해결 오류, 미구현 사항, 다음 작업, Git 상태. 09 양식 활용.

## 10. 접근 및 관리

Codex와 Claude Code 각각에서 Notion 연결 또는 문서 내보내기 파일을 사용할 수 있어야 한다. 이 페이지 작성만으로 외부 AI의 접근 권한이 설정되는 것은 아니다. 노션 기획과 Git 명세 간 변경 사항은 승인 후 함께 반영한다.
