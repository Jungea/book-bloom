# 06-4. 기존 프로젝트 참조 및 코드 재사용 가이드

> 확인: 2026-11-26
> 상태: 노션 원문 이관. 문서 안의 확정·제안·미정 표기를 그대로 따른다.

## 1. 목적

신규 프로젝트를 구성하고 기존 세 저장소를 병합하거나 전체 계승하지 않는다. 분야별 설계와 코드를 선별 참조하며 현재 확정 기획을 우선한다.

## 2. 참조 저장소

- [my-library](https://github.com/Jungea/my-library): 게임 규칙 및 테스트
- [PageRoom](https://github.com/Jungea/PageRoom): 독서관리 및 데이터 관리
- [Bookhive](https://github.com/Jungea/Bookhive): 게임 화면 및 기술 구조

## 3. 분야별 기준 저장소

## 4. 저장소별 활용 지침

### my-library

참조: 독서 활동과 게임 보상 연결, 손님 상태 머신, 대출·반납, 순수 함수 규칙·테스트, 저장소 계층 분리.
주의: Expo/React Native UI 직접 이전 금지, SQLite 구현 재작성, 상태 전환 및 시간 처리 검토, 실제 재고와 무관한 오프라인 보상 재사용 금지, 기존 포인트 대신 하트·평판 적용.

### PageRoom

참조: 도서 등록·수정, 독서 기록, 독후감 편집, 데이터 타입, Supabase 인증, PostgreSQL 모델, 사용자별 RLS, 테마·UI.
주의: Next.js 구조 그대로 이전 금지, Server Action은 Vite 환경에 맞게 재작성, 스키마 재설계, 마이그레이션 순서·정합성 검증, 미기획 콘텐츠 제외, 복수 데이터 생성 시 원자적 처리 검토.

### Bookhive

참조: React/Vite/TypeScript/Phaser 구성, 초기화·씬, GameCanvas, 이벤트 전달, 가로 화면, 캔버스 배율, 에셋 로딩, 스프라이트·애니메이션, 독서관리 Vite 포팅.
주의: StorePage 전체 이전 금지, 규칙·UI·저장·렌더링 분리, 기존 화면 비율·배치 대신 신규 목표 및 규격 적용, 퀘스트·업적·확장·손님 유형 일괄 이전 금지, 기존 에셋은 검증용만 고려, 기존 완독 보상 규칙 그대로 적용 금지. Capacitor는 기존 분석상 계획만 존재하므로 Android 신규 구성.

## 5. 현재 기획 우선 적용 규칙

- 최초 독서 시작 +1권, 최초 완료 +1권, 재독 완료 +1권. 독후감은 도서 가치 및 장르 전문성 증가, 추가 도서 획득 조건 아님.
- 하트·평판, 가로형 2D 벽면, 4슬롯, 시설 접근 좌표 및 단순 이동 경로 우선 검토.
- 오프라인 효율은 온라인보다 낮으며 하트·평판 획득 시간 한도 이후에도 대출·반납 계속.
- PC 웹 및 Android 지원, iOS 제외. 충돌 시 현재 기획 우선.

## 6. 코드 재사용 원칙

| 구분 | 설명 |

## 7. AI 코딩 도구 지침

- 저장소 임의 병합 금지, 작업별 기준 저장소 우선 참조, 참조 파일·기능 작업 결과에 기록.
- 현재 기획과 기존 구현 차이 확인, 미승인 기능 추가 및 의존성 일괄 설치 금지.
- 기존 테스트 통과 여부와 별개로 현재 규칙 검증, 알려진 오류 이전 금지, 원본 저장소 무단 수정 금지.
- Git 개발 시 docs/`reuse-guide.md`에 공통 지침을 관리하고 `AGENTS.md`와 `CLAUDE.md`에서 참조하도록 한다.

## 8. 초기 검증 목표

상세 단계는 08. MVP 및 개발 로드맵에서 관리한다.

- 1차: 신규 에셋 정적 화면, 4슬롯, PC 웹, Android APK 설치, 화면·에셋 비율, 손님 한 명 이동.
- 2차: 독서 시작·완료 보상으로 도서 획득, 책장 진열, 손님 입장, 대출·반납·보상, 새로고침·재실행 상태 복원.
- 3차: 계정 연동, PC·Android 동기화, 동일 도서관 이어서 이용, 중복 대출·보상 방지, 오프라인 진행.
각 단계 완료 후 추가 콘텐츠를 개발하며 기존 출시 버전 범위를 변경하지 않는다.

## 9. 최종 활용 방향

Bookhive는 화면·기술 구조, my-library는 최소 규칙·테스트, PageRoom은 독서관리·데이터 관리 기준. 신규 프로젝트는 Android 패키징, 신규 그래픽, 현재 기획 및 통합 구조를 담당한다.
본 가이드는 사용자 제공 저장소 분석을 기반으로 하며 실제 코드 재검증 및 파일별 재사용 결정은 개발 시 수행한다.
